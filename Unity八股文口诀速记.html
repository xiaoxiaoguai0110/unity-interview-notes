Unity 客户端八股文 · 口诀速记卡

一句话记住一个考点 · 配合《Unity客户端八股文-QA-结合项目》使用 · 每张卡都有记忆钩子

一、生命周期与脚本

醒启始 · 固更晚 · 禁毁
MonoBehaviour 生命周期执行顺序

Awake(醒) → OnEnable(启) → Start(始) → FixedUpdate(固) → Update(更) → LateUpdate(晚) → OnDisable(禁) → OnDestroy(毁)。同一帧先全部 Awake 再全部 Start。

相机跟随放 LateUpdate——"最后一个下班"。
Awake 管自己，Start 等别人
Awake 和 Start 的区别

Awake：缓存组件、初始化自身字段（未启用也执行）；Start：依赖其他对象已就绪的逻辑（如注册全局管理器）。

3DActGame 的 Player 在 Awake 缓存 InputReader/Animator/CharacterController/Health。
物理 Fixed、逻辑 Update、相机 Late
三个 Update 各干各的

FixedUpdate 固定步长（50Hz）跑物理；Update 每帧跑输入和逻辑；LateUpdate 最后跑相机跟随。移动刚体用 FixedUpdate + velocity/MovePosition。

"晚更新"晚在谁后面？角色和动画都更新完之后。
SetActive 整棵子树，enabled 只管自己
SetActive(false) 与 enabled=false

SetActive(false) 禁用整个 GameObject（含子物体）并触发 OnDisable；enabled=false 只停该组件回调。二者都不会停协程。

"禁用一个，禁用全家；禁用自己，别人照跑。"
组件引用 Awake 缓存，Update 只做正事
如何高效获取组件引用

避免每帧 GetComponent/Find；在 Awake 缓存，配合 [RequireComponent] 保证存在，可选组件用 TryGetComponent。

面试反例："每帧 GameObject.Find + GetComponent，等于每天翻通讯录找人。"

二、协程与异步

迭代器，挂起又恢复，主线程上不并行
协程原理

方法返回 IEnumerator，Unity 每帧调 MoveNext()，遇 yield return 挂起，按返回指令决定恢复时机。协程跑在主线程，不是多线程。

把它想成"游戏自己给自己设的闹钟"。
协程挂起不并行，线程并行不同步
协程 vs 线程

协程：单线程协作式调度，能挂起/恢复但不能并行，适合分帧处理；线程：真并行，适合耗时计算，但 Unity API 大多只能在主线程调用。

"协程是排队上厕所，线程是分开的多条队伍。"
WaitForSeconds 每次 new 都是垃圾
协程等待对象的 GC 优化

WaitForSeconds 是引用类型，高频 new 会产生堆分配；用 static readonly 缓存复用，或用 UniTask 彻底消除。

"同一秒的闹钟，买一个用到底。"
Invoke 靠字符串，改了名字就失灵
Invoke 的坑与 TimerManager 重构（3DActGame）

Invoke("DisableDamage", 0.5f) 方法名是字符串：编译不检查、不能传参、不能单独取消。改用 TimerManager.Instance.Schedule(0.5f, () => ...)：统一入口、可取消、可暂停、可池化。

面试原话："我早期用 Invoke，后来发现坑就重构了。"

三、物理系统

两边都有 Collider，一边要有 Rigidbody
碰撞/触发事件的触发条件

双方都要有 Collider，至少一方有 Rigidbody；勾选 IsTrigger 走触发事件，否则走碰撞事件。

"没刚体没人理你，没碰撞体你撞不到人。"
Trigger 无阻挡只检测，Collision 有阻挡带碰撞
OnTrigger 与 OnCollision 的区别

OnTriggerEnter：进入区域，只检测、不阻挡；OnCollisionEnter：物理接触，有阻挡和碰撞。3DActGame 的武器伤害检测就是 Box Collider(IsTrigger) + Rigidbody(IsKinematic)。

"触发器是安检门，碰撞体是一堵墙。"
velocity 物理推，MovePosition 平滑移，直改 transform 是作弊
刚体移动的三种方式

设 velocity：物理驱动；MovePosition：平滑且参与物理；直接改 transform.position：绕过物理引擎，破坏模拟。

"直改 transform 等于把物理引擎当摆设。"
CC 管人不吃力，RB 受力才真实
CharacterController vs Rigidbody（3DActGame）

玩家用 CharacterController：自带碰撞/斜坡处理，不受物理力影响；武器/特效用 IsKinematic Rigidbody：只检测不模拟；箱子、尸体这类受力物体才用动态 Rigidbody。

面试追问："你玩家为什么不用 Rigidbody？——因为我不想让怪一掌把玩家打飞。"

四、渲染与图形学

顶点、几何、光栅化，片元最后把色画
渲染管线大致流程

顶点着色（坐标变换）→ 几何处理（裁剪/图元装配）→ 光栅化（变成像素）→ 片元着色（算颜色），最后深度测试/混合输出。

"先摆骨架（顶点），再填像素（光栅化），最后上色（片元）。"
静动 Instance，SRP 图集，LOD 剔除
Draw Call 的优化方式

静态合批、动态合批、GPU Instancing、SRP Batcher，配套：图集（Atlas）、LOD、遮挡/视锥剔除。

"一桌菜一次上（合批），别一道一道端。"
RGBA32 四个字节，ASTC 一个字节，Mipmap 乘 1.33
纹理内存估算

内存 ≈ 宽 × 高 × 字节/像素。RGBA32 = 4B，ASTC 4x4 ≈ 1B；开 Mipmap 总量约 ×1.33。1024×1024 RGBA32 ≈ 4MB。

"移动端无脑 ASTC，画质换内存。"
ZTest 测深度，ZWrite 写深度，透明只测不写
深度测试与写入

ZTest：片元通过深度测试的条件（默认 LEqual）；ZWrite：是否写入深度缓冲。透明物体 ZWrite Off，从远到近混合，避免遮挡后面的透明物。

"ZTest 是进门查票，ZWrite 是进门后盖章。"
URP 轻量移动端，HDRP 高画质 PC/主机，内置兼容最稳
渲染管线怎么选

URP：轻量跨平台、移动端友好、SRP Batcher；HDRP：物理渲染高品质、面向 PC/主机；内置管线：兼容性最好但已维护中。

"手游上 URP，大作上 HDRP，老项目内置。"

五、Shader

Cull Front 外扩，背面画成描边
描边（Outline）原理

只渲染背面（Cull Front），顶点沿法线外扩，画黑色描边层；再正常渲染正面。

"给模型穿一件撑大的黑外套。"
半角算高光，PBR 讲守恒
Blinn-Phong 与 PBR 的区别

Blinn-Phong：用半角向量近似高光，公式简单、不守恒；PBR：基于微表面理论，金属度/粗糙度描述材质，能量守恒、跨光照环境表现一致。

"Blinn-Phong 是估算，PBR 是记账（守恒）。"
Ramp 纹理做色阶，配合描边成卡通
卡通渲染（Toon）

把漫反射 N·L 映射到 Ramp 纹理上，采样出色阶，形成硬边卡通光影；变体用 shader_feature 裁剪、ShaderVariantCollection 预编译。

"灰度值对着色卡选色，就是卡通。"
受击闪白 = 混白再衰减
受击闪白效果（3DActGame 可落地）

Shader 暴露 _FlashAmount，lerp(基色, 白, _FlashAmount)；C# 受击时顶到 1，再用协程 0.1s 衰减回 0，和 GetHit 动画同步。

"被打一下白一瞬，跟动画一起响。"

六、UGUI

Overlay 最上层，Camera 可被挡，World 世界放
Canvas 三种渲染模式

Screen Space Overlay：永远最上层；Screen Space Camera：渲染到指定相机、可被 3D 遮挡；World Space：世界空间 UI（血条、飘字）。

"血条是世界的，面板是屏幕的。"
重建、打断、Mask 多，Overdraw 拖后腿
UI 卡顿的常见原因

Canvas 重建频繁（改文本/颜色/位置）、合批被打断、Mask 过多、Overdraw、文本过多。

"UI 一卡，先查这四件事。"
动静分离，关 Raycast，RectMask 顶替，CanvasGroup 淡入淡出
UI 优化手段

频繁变化的 UI 单独放 Canvas；关闭无用 raycastTarget；用 RectMask2D 代替 Mask；隐藏用 CanvasGroup（alpha/interactable/blocksRaycasts）避免 SetActive 触发重建。

"常变的单住一个屋，别拉着全家重建。"

七、资源管理与热更新

Resources 打包里，AB 可热更要自管，Addressables 全自动
资源加载三兄弟

Resources：随包打进、不能热更、加载慢；AssetBundle：可独立打包远程下载，但要自己管依赖/卸载；Addressables：基于 AB 自动管引用计数和依赖。

"Resources 是背包里的，AB 是外卖可更新的，Addressables 是管家全包的。"
资源走 AB，逻辑走脚本
热更新方案

资源热更：AssetBundle + 版本清单 + 增量下载；逻辑热更：xLua/toLua、ILRuntime、HybridCLR（IL2CPP 下补充元数据 + 解释执行）。

"资源和逻辑分开更，只下增量最快。"
预创建、复用、重置，容量上限别忘记
对象池三要点

预创建一定数量 → 用 SetActive 复用 → OnDespawn 必须重置状态（血量、FSM、计时器），还要设容量上限。3DActGame 重构方向：受击特效/敌人池化。

"复用出来满血满状态，否则全是上个敌人的残魂。"
Retain +1，Release -1，归零才卸载
引用计数资源管理器

每个资源记录引用数，加载 +1、释放 -1，减到 0 才真正卸载，避免重复加载和泄漏。

"没人用了才退房，有人住着不退。"

八、内存与性能优化

装箱、拼接、每帧 new，LINQ 闭包要提防
如何降低 GC 分配

避免装箱、字符串拼接、每帧 new 临时对象、LINQ/闭包分配；缓存组件引用和 WaitForSeconds；用 NonAlloc 物理查询和对象池。

"每帧少造一个对象，GC 少忙一秒钟。"
事件没反注册，静态抱住大对象，协程没停 AB 没卸
内存泄漏常见原因

事件未反注册、静态字段持有对象、协程未停止、AssetBundle 未卸载、单例持有大对象、闭包被长期持有。

"OnDisable 记得 -=，否则 UI 死了还活着。"
CPU 看热点，GC 看分配，Memory 看快照
如何用 Profiler 定位性能问题

CPU 模块找耗时热点；GC Alloc 列抓分配；Memory 快照对比找泄漏；渲染面板看 Draw Call；最后真机 Profiler 验证。

"改一处、测一处，别凭感觉优化。"
优化要有数字，不然只是感觉
项目性能优化案例（KitchenChaos/3DActGame）

KitchenChaos：AI 冷却 0.8s → 0.15s 解决发呆；3DActGame：Invoke → TimerManager + 对象池，用 Profiler 记录 GC Alloc 前后对比。

面试只说这一句："重构后战斗场景 GC 从每帧 150KB 降到 0。"

九、动画系统

Trigger 一次性，Bool 持续态，Float 连续值
Animator 三类参数

Trigger：一次性触发（攻击/受击，用后自动复位）；Bool：持续状态（接地、跑步）；Float：连续值（Speed 驱动 Blend Tree）。3DActGame：OnAttack(Trigger)、ComboStage(int)、Speed(float)。

"Trigger 是按铃，Bool 是开关，Float 是油门。"
关键帧放判定，时机最精确
Animation Event 的用途（3DActGame）

攻击动画关键帧回调 OnAttackHit() 做扇形伤害判定、OnAttackEnd() 切回 Pursuit、OnGetHitEnd() 回 Idle。判定跟动画走，改了动画判定也跟上。

"刀挥到哪一帧命中，由美术说了算。"
动作位移用动画，玩家操控走代码，二者混用会抖
Root Motion vs 代码移动

Root Motion：位移由动画驱动，连招/受击位移天然一致；代码移动：响应快、可控，适合玩家操控和网络同步。混用会抖动，必须二选一。

"操控权要么给玩家，要么给动画，不能两个人抢方向盘。"

十、网络编程

TCP 可靠有序，UDP 快而糙，KCP 补可靠
TCP / UDP / KCP 选型

TCP：可靠有序，适合登录、结算；UDP：快但不可靠，适合实时战斗；KCP：在 UDP 上实现确认重传的可靠传输，低延迟，常用于帧同步。

"TCP 是挂号信，UDP 是飞鸽传书，KCP 是给鸽子配了对讲机。"
帧同步传输入、两端同算；状态同步传状态、服务器权威
帧同步 vs 状态同步

帧同步：只同步输入指令、各端跑相同逻辑，带宽低、可回放，要求确定性（定点数、统一随机种子、固定迭代顺序）；状态同步：服务器权威广播状态、客户端插值，防作弊好。

"帧同步是每人发同一张卷子；状态同步是老师统一公布答案。"
包头写长度，按长拆包，半包先攒着
TCP 粘包/拆包处理

TCP 是字节流没有消息边界：协议 = 4 字节长度 + 消息体；收到数据按长度解析，不足（半包）留在缓冲区等下一批。

"快递单上写包裹大小，拆不完的先放驿站。"
定期发心跳，超时判断线，指数退避重连
心跳与断线重连

定期发 Ping 探测连接；超时判定断线；重连成功后服务器下发快照/补状态；弱网加缓冲和预测。

"电梯里的对讲机，定期喊一声'还在吗'。"

十一、设计模式与架构

Instance 属性，Awake 查重，DontDestroy 常驻
MonoBehaviour 单例三件套（AudioManager）

static Instance + Awake 里查重销毁重复实例 + DontDestroyOnLoad 跨场景常驻。3DActGame 的 AudioManager 就是这么写的。

"全场只许有一个管家，多了就开除。"
数据只发事件，UI 只管订阅，销毁记得反注册
观察者模式 / 事件解耦

发布方不认识订阅方；UI 订阅数据事件被动刷新；OnDisable/OnDestroy 反注册防泄漏。KitchenChaos 的 OnRecipeSpawned 同时驱动订单 UI 和 AI。

"广播喊一声，谁要谁举手。"
状态封装方法，ChangeState 统一切换
状态模式（FSM）

把每个状态的行为封装成独立类/方法，用统一入口切换，状态间不互相干扰。3DActGame 敌人五状态（呆巡追攻挨）、KitchenChaos AI 四状态。

"一个人一个工位，切换走前台登记。"
配置与逻辑分离，改数值不重编译
数据驱动（ScriptableObject / 配置表）

数值放配置（SO/JSON），代码只读配置：改数值不用改代码、可热更、策划可自测。KitchenChaos 的 RecipeSO、3DActGame 的 AudioClipRefsSO。

"把数字从代码里赶出去，住进配置表。"

十二、你的项目专属口诀

呆 · 巡 · 追 · 攻 · 挨
3DActGame 敌人 FSM 五状态

Idle(呆) → Patrol(巡) → Pursuit(追) → Attack(攻) → GetHit(挨)。触发条件：距离、冷却、动画事件。

"先发呆，再巡逻，看到你就追，追上就砍，砍完就挨打。"
呆 · 走 · 切 · 等
KitchenChaos AI 显式状态机四状态

Idle(呆) → MovingToTarget(走) → Cutting(切) → Waiting(等)。每个状态一个 Update*() 方法，ChangeState() 统一切换。

"从散落 if-else 重构来的——单文件 500 行的教训。"
订单减台面，等于真正缺
KitchenChaos AI 差集算法

订单需要的 - 台子上已有的 = 真正缺的（list.Contains 差集）；数据量大时换 HashSet O(1) 查找；配套"原料追溯"和"按订单锁定装盘"。

"先算缺什么再动手，别乱拿导致死锁。"
排队缓冲，切回重置
3DActGame 五段连招系统

代码侧 ComboStage + 排队攻击；动画切回 Blend Tree 时重置连招。解决"Exit Time 与代码推进不同步"的已知问题。

"连招像排队取号：按了就排着，窗口空了就上。"
武器触发盒，敌人扇形检
3DActGame 两种伤害判定方式

玩家武器：Box Collider(IsTrigger) + Rigidbody(IsKinematic)；敌人攻击：Animation Event 关键帧触发扇形检测（距离 + 角度 ±60°）。

"一个等撞上来，一个主动扫过去。"
